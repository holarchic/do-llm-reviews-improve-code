# Architecture

A stdlib-Python harness (`eval/`) that replays real phases of loop-built repos, and the loop it measures (`skills/`).

## Subject under test

**Files:** `skills/build-loop/SKILL.md`, `skills/build-loop/references/code-architecture-rules.md`, `skills/codex-review/SKILL.md`, and the rest of `skills/`

A snapshot of codex-reviews-claudes-build-loop's skills, carried with their history from that repo. `prompts.py` reads the reviewer templates and rubric from here as bytes at call time, and every freeze hashes them, so a skill change lands here only as a deliberate copy followed by a new freeze. No session loads these as installed skills.

## Eval harness

**Files:** `eval/__main__.py`, `eval/harness/`, `eval/tasks/`, `eval/PREREG.md`, `eval/MANIFEST.json`, `eval/prereg/`, `eval/manifests/`, `eval/tests/`

The instrument: it measures whether the loop improves a model's code. Stdlib Python, run from the repo root as `python3 -m eval validate | probe | calibrate | freeze | run | judge | report | rounds | cost | spend | admit [--experiment NAME]`. Raw runs, transcripts and reports live in `eval/data/` (the pilot at its root, other experiments in `eval/data/<name>/`; gitignored, Dropbox-ignored).

- **Tasks** (`tasks.py`, `eval/tasks/<id>/`): writer-visible `TASK.md`; private hidden suite, reference, wrong variants and traps. Optional parts: the follow-up group (`FOLLOWUP.md` and its suite, reference and wrong variants), a degraded reference (judge calibration) and planted bugs (`mutants/`, reference copies with one bug each). `validate` checks whatever a task has — each suite passes its reference and fails every wrong variant; each mutant fails the hidden suite but passes at least half of it — then writes `expected.json`, the frozen test IDs every score divides by. `validate --task ID` (repeatable) checks only the named tasks. A task that a written manifest freezes (`frozen.py` reads them all) is skipped by bare `validate` and refused by name, so its `expected.json` is never rewritten. `dev-*` tasks exercise the harness and are never scored. A corrected task is a copy, `<id>-v2`, beside its frozen original: each of the six replay tasks has a v2 whose TASK.md agrees, statement by statement, with the tests that score it, and whose `audit.md` records that check.
- **Replay tasks** (`source.py`): a task with `source.json` rebuilds a feature in a real repository. `source.json` pins three commits, `base`, the original pre-review build (`pre_review`) and the landed `reference`, plus a control flag for a phase review left almost untouched. The commits come from a bare mirror under `eval/data/sources/` and are exported with `git archive`, so no session sees history. The seed is base plus TASK.md. Hidden tests are `tests/test_hidden_feature_*.py` and `tests/test_hidden_review_*.py`, and `defects.json` maps each review-caught defect to its tests. `validate` requires:
  - every hidden test passes on reference;
  - every feature test fails on base;
  - every review test reaches its defect on pre_review: an assertion failure at the call stage, or a crash the defect record names, never a missing name;
  - anchors run three rounds, the last under concurrent load, and any flaky test is refused.

  `score_build` replaces the build's `tests/` with base's tests plus the hidden modules. It reports the share of defects avoided, the share of feature tests passed and the share of base tests broken.
- **Sessions** (`agents.py`, `audit.py`, `procs.py`, `providers.py`, `openrouter.py`): every model call goes through `agents.run(Agent(cli, model, provider), …)`, dispatching to `run_claude` or `run_codex`, which own the isolation flags, tool policy per role (writer, reviewer, judge), timeouts and the terminal class (completed, timeout, infra). Either CLI can be the writer; prompts travel on stdin. Claude runs with project-only settings and a fail-closed Bash sandbox that denies reads of private roots; Codex runs from a throwaway home under an outer Seatbelt profile that denies private reads and writes and lets only a writer write its run dir. Run dirs and Codex homes are random names under a runs root no session can list (`audit.anonymous_workdir`). `audit.py` also records tool calls that name a private path, as a diagnostic. `procs.py` runs each child in its own process group and kills the group on timeout. A routed agent (provider `openrouter` or `deepseek`, the table in `providers.py`) is routed by its CLI's own settings, always to its route on the routing proxy (Spend, below): Claude Code gets the route base plus the provider's Claude path (`/anthropic` for DeepSeek) as its base URL, every model alias mapped to the routed model, and its key through `apiKeyHelper` (never an environment); Codex gets a provider block (the route base plus the provider's Codex path, `/v1` for OpenRouter, the root for DeepSeek) and holds the key in its process environment under the provider's variable, with every provider's credential variable excluded from its tool shells. Each provider's key dir is a private root. `providers.scrub` redacts every installed provider key from saved files (dropping a repo whose history holds one), gated on `Agent.routed`; an `Agent` names `native` or a table entry. `openrouter.py` keeps pilot 2's prices and `spent`, which reads pilot 2's spend-cap ledger for its report. An offline experiment (the replay) gives Claude's Bash sandbox no network beyond localhost, and runs Codex behind `egress.Proxy`, a per-session CONNECT proxy admitting only its model hosts, under a Seatbelt rule that denies every other outbound connection, Unix sockets included; Codex web search is off. `probe.py` proves the isolation with positive controls, on the experiment's own agents (`probe_plan`), with a key and a pass-through probe for each routed CLI and provider and, offline, a network probe for each writer and reviewer, whose model-call control is the egress proxy's CONNECT for a native Codex session and, for a routed one, a request its envelope's proxy admitted and the model answered, with nothing admitted by egress.
- **Runs** (`loop.py`, `prompts.py`): an `Arm` names its writer and reviewer agents and its ablation switches (writer rules, plan review, review passes). `execute_run` takes one task × arm from an empty repo (or a replay task's seed, with brownfield prompts) to a scored build, committing after each writer step so infrastructure retries restart from HEAD; `execute_followup` applies FOLLOWUP.md to a copy of a finished build. `prompts.py` builds reviewer prompts from the shipped `codex-review` templates and rubric, read as bytes at call time. When those templates ask for a `Basis:`, `parse_verdict` reads a HIGH/MEDIUM issue without one as LOW and the writer is told each issue's effective severity.
- **Scoring** (`score.py`, `runner.py`, `planted.py`): `runner.py` runs a hidden suite inside the candidate's process with a per-test alarm and streams results, so a killed run still scores finished tests; `score.py` adds static metrics and `run_in_place` (a build's own tests, run from one copy as discovery root, import root and cwd). For a task with planted bugs, `planted.py` overlays the reference and then each mutant onto fresh copies of the build and runs the build's tests (unittest's default `test*.py`): a mutant is caught when a test that passes on the reference fails on it.
- **Judging** (`judge.py`): blind pairwise comparison of two builds by one Claude and one Codex frontier model, in both orders, plus calibration against degraded references. A build from an empty repo is shown as its Python files. A replay build is shown as its patch from the task's starting tree, every changed file whole, markdown and `plans/` left out; it has no calibration, and a pair over `PROMPT_CHARS` is judged on its source alone. `pilot.judge_schedule` pairs replicate r of each arm, and `pilot.current_judgement` drops a judgement whose builds were rebuilt.
- **Experiments** (`experiments.py`, `manifest.py`, `pilot.py`, `records.py`, `report.py`, `replicated.py`): an `Experiment` names its tasks, arms, judged pairs, replicates, parallelism, seed, data dir, pre-registration, report kind and, when routed, the spend envelope it draws on (pilot 2's own `budget_usd` cap is history, read by its report); `pilot`, `pilot2` (open-weight models through OpenRouter, replicated and judge-free) and tier, reverse-direction and ablation experiments are registered. Run ids are `<task>--<arm>`, plus `--r<n>` for replicates. `freeze --experiment X` hashes X's pre-registration, the harness, the scored tasks and the shipped skill files into X's own manifest (`eval/MANIFEST.json` for the pilot, `eval/manifests/<name>.json` otherwise); `run`, `judge` and `report` refuse to start if any changed, so an experiment's report is regenerated from its freeze commit once the harness moves on. `pilot.py` runs an experiment's seeded schedule a few jobs at a time, never two of one task at once, reserves each routed job's estimate in its envelope (Spend, below), and resumes by skipping records `records.py` validates; `run_calibration` builds unfrozen tasks apart (`calibration/`), drawing on the experiment's envelope like its scored runs, for difficulty and cost screening. A routed run flags any session that reports a model it was not routed to, and scrubs the key from its exec dir after writing the record. `report.py` renders a judged experiment and applies the pilot's rule; `replicated.py` renders a replicated one from task means and applies pilot2's rule; `replay.py` renders the `replay` experiment (Opus solo, Opus self-review, Opus with Codex). Its arms are staged: `run --arm` builds one arm across every task and replicate, and a run without self-review is complete unless the loop beats solo. The design judgment of loop against solo is shown apart, per caught task, and never enters the verdict. Its rule needs four checks to pass on caught tasks: +15 points of defects avoided, wins on two-thirds of tasks, a feature-test loss of 5 points at most, and no rise in regressions. A comparison is uninformative when the comparator leaves no headroom. Other experiments are descriptive until their pre-registration defines a rule.
- **Guards** (`guards.py`): the harm guards a registered comparison applies, as pure functions over test counts. The regression guard takes each task's per-replicate failure counts for treatment and comparator (`failures` counts the frozen regression ids a build did not pass). Δ_t is their difference as a share of the task's tests, averaged over replicates, in exact fractions. It passes on a task mean of at most 0.5 and no Δ_t above 1.0, with zero tolerance as a sensitivity verdict. `feature_ok` is the −5 feature floor, and `headroom` checks the comparator's review mean and open caught tasks for a +threshold gain. The caller chooses the tasks: caught tasks and controls for regressions, caught tasks only for feature and headroom. v1's `replay.py` keeps its own zero-tolerance guard, frozen.
- **Costs** (`prices.py`, `ledger.py`, `spend.py`, `cost_report.py`): `prices.py` is the dated list-price table, per provider and model, with cache writes by duration and per-request long-context tiers. It is frozen with the harness, and every output names its date and sha256. `ledger.py` knows CLIs and prices, not runs, and imports only `prices.py`. It parses one attempt's usage at its boundary into typed tokens, or an unknown with a reason (core counters are required), then prices it for a `Seat` (CLI, price-table provider, model). Claude is priced from the last cumulative `modelUsage` (`usage["by_model"]`, or read back from the attempt's transcript). Codex is priced per request from its rollout counts when they reconcile with the session totals, otherwise from the totals, as a low–high range across a tier. An unpriced model raises, and fast mode, priority tier and US-only inference are unknown. `spend.py` walks a run's saved executions with the runner's own conventions (`loop.attempt_dir`, and the agent `loop._step` records on each step; a record made before that resolves its agent by the step's name). Every saved execution counts: the scored one, and the rest as spend that was not scored, an unreadable record as one unknown. `agents.py` records what the ledger needs: Codex's per-request counts and rate-limit snapshots from its kept rollout, and Claude's `by_model`. `cost --experiment X` renders it by arm, task, step and model into `eval/data/<experiment>/cost.md`.
- **Spend** (`envelope.py`, `route_config.py`, `proxy.py`, `settlers.py`, `routing.py`, `spend_commands.py`): a hard bound on final billed liability for routed sessions.
  - `envelope.py`: one ledger per budget, in `eval/data/envelopes/<name>.json` (Phase B's is `B`), named by every experiment and preparation step that draws on it (`Experiment.envelope`).
    - **What it holds:**
      - funding (credit, fees, taxes);
      - billing scopes: one provider key each, with its opening usage and allocation. A scope is fixed once registered, and a key belongs to one envelope, checked under a shared registry lock;
      - routes: policy, max charge, slots, upstream, and a stage, `probe` → `validated`. Any change returns a route to `probe`;
      - every admitted request: unresolved until settled, owned by job and attempt, keeping the bound and upstream it was admitted under;
      - job reservations: full holds at 1.5× the estimated cost, closed once the job has finished and its last request settled. A job id reopened for a fresh execution gets a fresh hold, its earlier spend counted as other spend (its `baseline`);
      - per-attempt refusals.
    - **What it enforces:**
      - funded credit + fees + taxes + Σ slots × max charge ≤ the envelope;
      - per scope, settled spend + each unresolved request's bound + the candidate's ≤ the allocation;
      - no request may eat into another job's hold;
      - reconciliation is one-sided, and an excess on any key refuses everything. There's a freshness rule.
    - **How it writes:** loading checks shapes and the financial invariants. One owner process holds a flock, and each transition persists a copy by atomic replace with a directory fsync before swapping it in. A closed owner refuses every write, and a failed write closes the owner, since the file may hold either state; a new owner reloads it.
    - **Typed views:** `route` and `pending_settlements`, each with its scope's key fingerprint (a pending one also carries its metered figure, invalidity and completion), `scopes`, the scope names, and `answered(attempt)`, the network probe's model-call evidence. `summary` lists the served values per route.
    - **Usage readings** are signed (a metered scope reads −balance) and cumulative: one below the last snapshot, or a first one below the opening usage, sets the scope's persistent `fault`, which refuses every admission and reservation until `spend clear-fault`.
  - `route_config.py`: a route's configuration as typed records, `Policy` and `Upstream`, and `request_problem`, the one check of a request against its policy. A route's max charge comes from the endpoint's context window and enforced output cap (`prices.request_charge_bound`); the policy keeps a request inside what that prices, with only text and tool content in `messages`, `input` and `system`. `max_body_bytes` is a transport limit.
  - `proxy.py`: the loopback reverse proxy every routed model request passes through.
    - Per-attempt URL tokens give each request an owner.
    - The policy is an allowlist (exact path, exact model, allowed top-level fields and tool types, text and tool content only, output cap where enforced), parsed once per route version. Every credential header (Bearer `Authorization`, `x-api-key`) must carry the same key, whose fingerprint must be the route's; both checks come before any upstream call, and the forwarded headers carry exactly that key.
    - Admission goes through the envelope. The response is requested unencoded and streams back unchanged, while the settler reads the billing id from the parsed events.
    - Shutdown refuses new requests, then gives in-flight handlers, a last settlement round and the workers until a deadline (each on its own thread, so a hung lookup can't hold it). Anything still running after that is fenced off by the closed owner, which refuses every write. A start that fails after the listener is up shuts it down again.
  - `settlers.py`: provider billing adapters, with typed outcomes `Billed` (with the provider that served it, when told) / `NotBilled` / `Pending`. Two kinds: OpenRouter's is billed, settled from `/generation`'s figure; DeepSeek's is metered, since DeepSeek reports no per-request charge: `Settler.read(event)` is a pure per-event reading (usage priced at the route model's peak rates, or `Invalid`; the served model; protocol completion), which the proxy records on the request, and a request settles only when its stream completed with one valid usage figure. Its reconciliation reading is −(the USD balance). A settler belongs to one billing scope: `from_upstream` checks the key file against the scope's fingerprint, or raises `NoSettler`, and the proxy then admits nothing on that route. OpenRouter reads the generation lookup and key usage (the one usage reader, finite and non-negative or `UsageUnavailable`; `spend scope` reads opening usage through it), with billing ids at fixed paths only.
  - `routing.py`: the process context. `active` (process-wide) and `job` (per thread), `session_base` and `refusal`, and `for_envelope`, which owns, serves and activates, then exits in reverse.
    - `agents.run_claude` / `run_codex` refuse a routed session outside it, and point the CLI's base URL at the proxy.
    - A refused session carries `spend_refused` and ends INFRA, and `loop._step` doesn't retry it.
  - **Wiring:** `pilot.routing_context`, `job_estimate` and `reserved` gate scored builds (each with its follow-up, resumed ones included), calibration, probes and dev runs. `job_estimate` prices only the attempts on the arm's routed seats (`spend.run_cost(..., seats)`), so a native seat's cost or missing price never moves a reservation; a calibration build that never reached a routed seat falls back to the bootstrap. A seat is routed when `Agent.routed`; an `Agent` names a known provider or raises. `prices.request_charge_bound` gives a route's worst case.
  - **CLI:** `spend_commands.py` handles `spend create | fund | scope | allocate | route | validate-route | status | resolve | clear-fault --envelope NAME`, parsing each action's flags (policy and upstream through `route_config`, a known settler name) before touching the envelope; `status` reads without ownership.
- **Admission** (`admission.py`, `admit_commands.py`): the paid checks that admit a routed path into B, run by `admit cache | metering | exhaustion` on the `admission` experiment (every candidate route under Claude Code and Codex, never scheduled or scored) inside B's envelope, exhaustion in its own.
  - **Checks:** each returns a typed `Result`, pass, fail or inconclusive, with its evidence; inconclusive never admits, and `spend validate-route` stays the operator's act.
    - `cache_and_served`: one session. The billed saving must be 80–105% of the saving the route's rates promise, on the provider's own token counts. Every request must be served as the route says (Z.AI for GLM; the route's model for DeepSeek).
    - `metering`: inside a DeepSeek peak window, the account's balance fall agrees with the metered total within the balance's precision. The account must be quiet for 30 minutes before and after, and the workload must carry cached input and reasoning worth 3× the tolerance each.
    - `exhaustion`: drain an account through the proxy until the provider refuses. The refusal must hold with less than one request's cost left, and the overdraw must stay within Σ slots × max charge.
  - **Dependencies:** the clock, sessions, balance, raw requests and settlement are injected (`Deps`), so the tests drive time and the provider.
  - **Records:** written to `eval/data/admission/<route>/`, `running` before any spend, never overwritten, each bound to the route version, key, endpoint, CLI version and price table. `admit status` marks a result stale when its binding changes; exhaustion holds per named provider account (`spend scope --account`). `admit budget` gives what is left of the $150 after the exhaustion runs.
  - **Proxy behaviour it relies on:** a provider's pre-generation refusal (a 402 or 429 with a JSON error and no billing id) settles as not billed with its evidence, so a refused request frees its slot.
- **Rounds** (`rounds.py`): `rounds --experiment X --arm Y` re-scores each code-review round of a replay arm's reviewed builds under `eval/prereg/<X>-rounds.md`. Round 0 is a build's `build` commit and round k its `fix-k` commit, each found in the exec's `repo/` by the writer step name its record lists (records hold no commit ids). Stop kinds come from the flags: capped, passed (carried forward to round 4) or truncated (absent past its last round). `verify_freeze` checks every file in the experiment's manifest except the CLI and `loop.py`, so it refuses once a task or scoring module moves. `score_rounds` exports each commit with `loop.materialize_head` and scores it with `source.score_build`, in parallel, into `eval/data/<X>/rounds/<run-id>/<exec>/round-<k>/score.json`. It writes atomically and resumes, and a stored score is reused only for the same commit and only if it passes the record validator. `collect` reads the scores back, `decide` applies the A3-2 trigger (task-balanced round-1 share of the final gain in defects avoided; INCOMPLETE on any missing build or round), and `render` writes the curve, the per-build table and a per-test reproduction check of each last round against its record.
- **Census** (`eval/census/`): `BRIEF.md` is the classification brief for review-fix commits in real build-loop repos; `SUMMARY.md` gives the aggregate counts. Rows from private repos stay local.
