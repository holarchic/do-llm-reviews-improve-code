# Architecture

A stdlib-Python harness (`eval/`) that replays real phases of loop-built repos, and the loop it measures (`skills/`).

## Subject under test

**Files:** `skills/build-loop/SKILL.md`, `skills/build-loop/references/code-architecture-rules.md`, `skills/codex-review/SKILL.md`, and the rest of `skills/`

A snapshot of codex-reviews-claudes-build-loop's skills, carried with their history from that repo. `prompts.py` reads the reviewer templates and rubric from here as bytes at call time, and every freeze hashes them, so a skill change lands here only as a deliberate copy followed by a new freeze. No session loads these as installed skills.

## Eval harness

**Files:** `eval/__main__.py`, `eval/harness/`, `eval/tasks/`, `eval/PREREG.md`, `eval/MANIFEST.json`, `eval/prereg/`, `eval/manifests/`, `eval/tests/`

The instrument: it measures whether the loop improves a model's code. Stdlib Python, run from the repo root as `python3 -m eval validate | probe | calibrate | freeze | run | judge | report | rounds [--experiment NAME]`. Raw runs, transcripts and reports live in `eval/data/` (the pilot at its root, other experiments in `eval/data/<name>/`; gitignored, Dropbox-ignored).

- **Tasks** (`tasks.py`, `eval/tasks/<id>/`): writer-visible `TASK.md`; private hidden suite, reference, wrong variants and traps. Optional parts: the follow-up group (`FOLLOWUP.md` and its suite, reference and wrong variants), a degraded reference (judge calibration) and planted bugs (`mutants/`, reference copies with one bug each). `validate` checks whatever a task has — each suite passes its reference and fails every wrong variant; each mutant fails the hidden suite but passes at least half of it — then writes `expected.json`, the frozen test IDs every score divides by. `validate --task ID` (repeatable) checks only the named tasks. A task that a written manifest freezes (`frozen.py` reads them all) is skipped by bare `validate` and refused by name, so its `expected.json` is never rewritten. `dev-*` tasks exercise the harness and are never scored. A corrected task is a copy, `<id>-v2`, beside its frozen original: each of the six replay tasks has a v2 whose TASK.md agrees, statement by statement, with the tests that score it, and whose `audit.md` records that check.
- **Replay tasks** (`source.py`): a task with `source.json` rebuilds a feature in a real repository. `source.json` pins three commits, `base`, the original pre-review build (`pre_review`) and the landed `reference`, plus a control flag for a phase review left almost untouched. The commits come from a bare mirror under `eval/data/sources/` and are exported with `git archive`, so no session sees history. The seed is base plus TASK.md. Hidden tests are `tests/test_hidden_feature_*.py` and `tests/test_hidden_review_*.py`, and `defects.json` maps each review-caught defect to its tests. `validate` requires:
  - every hidden test passes on reference;
  - every feature test fails on base;
  - every review test reaches its defect on pre_review: an assertion failure at the call stage, or a crash the defect record names, never a missing name;
  - anchors run three rounds, the last under concurrent load, and any flaky test is refused.

  `score_build` replaces the build's `tests/` with base's tests plus the hidden modules. It reports the share of defects avoided, the share of feature tests passed and the share of base tests broken.
- **Sessions** (`agents.py`, `audit.py`, `procs.py`, `openrouter.py`): every model call goes through `agents.run(Agent(cli, model, provider), …)`, dispatching to `run_claude` or `run_codex`, which own the isolation flags, tool policy per role (writer, reviewer, judge), timeouts and the terminal class (completed, timeout, infra). Either CLI can be the writer; prompts travel on stdin. Claude runs with project-only settings and a fail-closed Bash sandbox that denies reads of private roots; Codex runs from a throwaway home under an outer Seatbelt profile that denies private reads and writes and lets only a writer write its run dir. Run dirs and Codex homes are random names under a runs root no session can list (`audit.anonymous_workdir`). `audit.py` also records tool calls that name a private path, as a diagnostic. `procs.py` runs each child in its own process group and kills the group on timeout. An OpenRouter agent (`openrouter.py`) is routed by its CLI's own settings: Claude Code gets the base URL, every model alias mapped to the routed model, and its key through `apiKeyHelper` (never an environment); Codex gets a provider block and holds the key in its process environment, excluded from its tool shells. The key file's dir is a private root. `openrouter.scrub` redacts the key from saved files (dropping a repo whose history holds it), and `SpendCap` admits jobs while the key's spend since a phase began stays under that phase's cap, keeping each phase's baseline in a ledger across resumes. An offline experiment (the replay) gives Claude's Bash sandbox no network beyond localhost, and runs Codex behind `egress.Proxy`, a per-session CONNECT proxy admitting only its model hosts, under a Seatbelt rule that denies every other outbound connection, Unix sockets included; Codex web search is off. `probe.py` proves the isolation with positive controls, on the experiment's own agents (`probe_plan`), with a key probe for each routed CLI and, offline, a network probe for each writer and reviewer.
- **Runs** (`loop.py`, `prompts.py`): an `Arm` names its writer and reviewer agents and its ablation switches (writer rules, plan review, review passes). `execute_run` takes one task × arm from an empty repo (or a replay task's seed, with brownfield prompts) to a scored build, committing after each writer step so infrastructure retries restart from HEAD; `execute_followup` applies FOLLOWUP.md to a copy of a finished build. `prompts.py` builds reviewer prompts from the shipped `codex-review` templates and rubric, read as bytes at call time. When those templates ask for a `Basis:`, `parse_verdict` reads a HIGH/MEDIUM issue without one as LOW and the writer is told each issue's effective severity.
- **Scoring** (`score.py`, `runner.py`, `planted.py`): `runner.py` runs a hidden suite inside the candidate's process with a per-test alarm and streams results, so a killed run still scores finished tests; `score.py` adds static metrics and `run_in_place` (a build's own tests, run from one copy as discovery root, import root and cwd). For a task with planted bugs, `planted.py` overlays the reference and then each mutant onto fresh copies of the build and runs the build's tests (unittest's default `test*.py`): a mutant is caught when a test that passes on the reference fails on it.
- **Judging** (`judge.py`): blind pairwise comparison of two builds by one Claude and one Codex frontier model, in both orders, plus calibration against degraded references. A build from an empty repo is shown as its Python files. A replay build is shown as its patch from the task's starting tree, every changed file whole, markdown and `plans/` left out; it has no calibration, and a pair over `PROMPT_CHARS` is judged on its source alone. `pilot.judge_schedule` pairs replicate r of each arm, and `pilot.current_judgement` drops a judgement whose builds were rebuilt.
- **Experiments** (`experiments.py`, `manifest.py`, `pilot.py`, `records.py`, `report.py`, `replicated.py`): an `Experiment` names its tasks, arms, judged pairs, replicates, parallelism, seed, data dir, pre-registration, report kind and, when routed, a spend cap; `pilot`, `pilot2` (open-weight models through OpenRouter, replicated and judge-free) and tier, reverse-direction and ablation experiments are registered. Run ids are `<task>--<arm>`, plus `--r<n>` for replicates. `freeze --experiment X` hashes X's pre-registration, the harness, the scored tasks and the shipped skill files into X's own manifest (`eval/MANIFEST.json` for the pilot, `eval/manifests/<name>.json` otherwise); `run`, `judge` and `report` refuse to start if any changed, so an experiment's report is regenerated from its freeze commit once the harness moves on. `pilot.py` runs an experiment's seeded schedule a few jobs at a time, never two of one task at once, admits each job under the spend cap, and resumes by skipping records `records.py` validates; `run_calibration` builds unfrozen tasks apart (`calibration/`) under their own cap, for difficulty and cost screening. A routed run flags any session that reports a model it was not routed to, and scrubs the key from its exec dir after writing the record. `report.py` renders a judged experiment and applies the pilot's rule; `replicated.py` renders a replicated one from task means and applies pilot2's rule; `replay.py` renders the `replay` experiment (Opus solo, Opus self-review, Opus with Codex). Its arms are staged: `run --arm` builds one arm across every task and replicate, and a run without self-review is complete unless the loop beats solo. The design judgment of loop against solo is shown apart, per caught task, and never enters the verdict. Its rule needs four checks to pass on caught tasks: +15 points of defects avoided, wins on two-thirds of tasks, a feature-test loss of 5 points at most, and no rise in regressions. A comparison is uninformative when the comparator leaves no headroom. Other experiments are descriptive until their pre-registration defines a rule.
- **Guards** (`guards.py`): the harm guards a registered comparison applies, as pure functions over test counts. The regression guard takes each task's per-replicate failure counts for treatment and comparator (`failures` counts the frozen regression ids a build did not pass). Δ_t is their difference as a share of the task's tests, averaged over replicates, in exact fractions. It passes on a task mean of at most 0.5 and no Δ_t above 1.0, with zero tolerance as a sensitivity verdict. `feature_ok` is the −5 feature floor, and `headroom` checks the comparator's review mean and open caught tasks for a +threshold gain. The caller chooses the tasks: caught tasks and controls for regressions, caught tasks only for feature and headroom. v1's `replay.py` keeps its own zero-tolerance guard, frozen.
- **Costs** (`prices.py`, `ledger.py`, `cost_report.py`): `prices.py` is the dated list-price table, per provider and model, with cache writes by duration and per-request long-context tiers. It is frozen with the harness, and every output names its date and sha256. `ledger.py` parses each attempt's usage at its boundary into typed tokens, or an unknown with a reason, then prices it. Claude is priced from the last cumulative `modelUsage` (`usage["by_model"]`, or read back from the attempt's transcript). Codex is priced per request from its rollout counts when they reconcile with the session totals, otherwise from the totals, as a low–high range across a tier. An unpriced model raises, and fast mode, priority tier and US-only inference are unknown. Every saved execution counts: the scored one, and the rest as spend that was not scored. `agents.py` records what the ledger needs: Codex's per-request counts and rate-limit snapshots from its kept rollout, and Claude's `by_model`. `cost --experiment X` renders it by arm, task, step and model into `eval/data/<experiment>/cost.md`.
- **Rounds** (`rounds.py`): `rounds --experiment X --arm Y` re-scores each code-review round of a replay arm's reviewed builds under `eval/prereg/<X>-rounds.md`. Round 0 is a build's `build` commit and round k its `fix-k` commit, each found in the exec's `repo/` by the writer step name its record lists (records hold no commit ids). Stop kinds come from the flags: capped, passed (carried forward to round 4) or truncated (absent past its last round). `verify_freeze` checks every file in the experiment's manifest except the CLI and `loop.py`, so it refuses once a task or scoring module moves. `score_rounds` exports each commit with `loop.materialize_head` and scores it with `source.score_build`, in parallel, into `eval/data/<X>/rounds/<run-id>/<exec>/round-<k>/score.json`. It writes atomically and resumes, and a stored score is reused only for the same commit and only if it passes the record validator. `collect` reads the scores back, `decide` applies the A3-2 trigger (task-balanced round-1 share of the final gain in defects avoided; INCOMPLETE on any missing build or round), and `render` writes the curve, the per-build table and a per-test reproduction check of each last round against its record.
- **Census** (`eval/census/`): `BRIEF.md` is the classification brief for review-fix commits in real build-loop repos; `SUMMARY.md` gives the aggregate counts. Rows from private repos stay local.
